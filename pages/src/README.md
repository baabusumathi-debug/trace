# How a study page is built

Each page under `/pages/` is generated by a small Python pipeline, one folder per page.
The generator is kept here so any later session can rebuild or extend a page instead of
editing 250 KB of generated HTML by hand.

## The four parts

| File | What it holds |
|---|---|
| `content*.py` | the writing: title, sections, the cards in each section, the prose for every card, mimic pairs, traps. No HTML. |
| `vis*.py` | generic visual renderers — three-number panels, flows, branches, cycles, grids, ladders, tables, split comparisons, step strips, chips. Each returns an HTML fragment. |
| `draw.py` | hand-drawn SVG diagrams for that subject (hearts, pressure loops, echo views, Starling curves, ultrasound windows). Shock I only so far. |
| `build*.py` | merges the content with the source data (the viva packet JSON), picks the visual per concept, and writes the finished single-file HTML into `/pages/`. |

`style.css` and `app.js` are the page's own styling and screen routing; `build.py` inlines them.

## The order that matters

1. **Gather the material first.** Read the packet/cards and write the prose.
2. **Then choose the visual** for each concept. Never the other way round — picking a
   layout before there is content produces a polished page with thin content.
3. **Then QA visually.** `check.py` walks every screen in headless Chrome, measures
   unexpected overflow, counts the reveals, and screenshots at phone and tablet widths.
   A page is not finished until that walk is clean.

## Rebuilding

```bash
cd pages/src/shock1 && python3 build.py      # writes ../../shock1.html
cd pages/src/shock1 && python3 check.py      # walks every screen, reports overflow
```

`build.py` asserts that every card code it writes matches the packet it came from, so a
mismatch fails the build rather than shipping a wrong card.

## Design rules these pages follow

- Tiles and tabs, never one endless scroll.
- A different visual per concept — numbered boxes alone are not structure.
- A mimic pair shows what makes the two look **alike** first, then the one thing that
  separates them.
- Anything colour-coded also carries a symbol or a label.
- Wide diagrams keep their size and scroll sideways rather than shrinking to illegible.
